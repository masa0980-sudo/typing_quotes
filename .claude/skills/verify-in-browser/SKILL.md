# ブラウザでの動作確認

テストフレームワークは入れていない。動作確認は**実際にブラウザで打ってみる**のが唯一の手段。

## 手順

1. 開発サーバーを起動する（バックグラウンドで）。
   ```
   .claude/scripts/dev.sh 3111
   ```
   ログに `Ready` が出るまで待ってから開くこと。

2. Playwrightで開く。ブラウザは `/opt/pw-browsers/chromium` にプリインストール済み。
   `executablePath: "/opt/pw-browsers/chromium"` を明示し、**`playwright install` は実行しない**
   （再ダウンロードになって失敗する）。

3. 画面は `title → countdown → playing → reveal → playing → … → result` と進む。
   - タイトルで `日本語` / `English` を選び `START`
   - 打鍵は `page.keyboard.type()` ではなく1文字ずつ `press` する方が判定を追いやすい
   - **1問打ち切ると `reveal`（出典と背景の解説）が挟まる**。`Enter` か `Space` で次へ
   - `Esc` でいつでもタイトルへ戻る

4. スクリーンショットはスクラッチパッドに保存し、`Read` で目視確認する。

## 見るべきポイント

- **reveal画面** … 出典(`source`)と「この言葉について」(`note`)が両方出ているか。
  ここが今作の売りなので、名言データを触ったら必ず1問は最後まで打って確認する。
- **ローマ字の複数表記** … `romaji.ts` を触ったら、少なくとも
  `んと` を `nnto` と `nto` の両方で打てること、`きっと` を `kitto` と `kixtuto` の
  両方で打てることを確認する。ここは `inputChar()` の判定順序を変えると壊れる。
- **英語モード** … 大文字を Shift なしで打てるか。

## 既知の制約（ハマりどころ）

- **`output: "export"` でビルド時にプリレンダリングされる。**
  初期stateで出題をシャッフルするとハイドレーション不一致になるので、
  乱数は `START` アクションの中、`localStorage` 読み込みは `useEffect` の中で回している。
  ここを動かしたら、ブラウザのコンソールにハイドレーション警告が出ていないか必ず見る。
- **サンドボックスからは `*.github.io` に到達できない。**
  公開URLでの表示確認はこの環境では不可能。ローカルで確認し、
  **報告するときは「公開URLでの実表示は未確認」と明示する**（できたことにしない）。
- `npm run build` は静的エクスポートなので、`out/` を `python3 -m http.server` で配信しても
  確認できる。ただし `basePath` を付けたい場合は `GITHUB_PAGES=true` が要る
  （その場合 `out/` をそのまま配信するとパスが合わないので、開発サーバーで見る方が早い）。
