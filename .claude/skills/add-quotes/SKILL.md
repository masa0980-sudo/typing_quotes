# 名言を追加する

データは `src/lib/quotes/` に分野ごとに分かれていて、`index.ts` が自動で連結する。
**追加するときに触るのは分野ファイル1つだけ**（`index.ts` の編集は不要）。

| ファイル | 内容 |
|---|---|
| `science.ts` | 科学者・発明家 |
| `philosophy.ts` | 哲学者・思想家 |
| `society.ts` | 政治家・社会運動家 |
| `arts.ts` | 芸術家・作家 |
| `japan.ts` | 日本の偉人 |
| `short.ts` | 短くて打ちやすいもの（初心者向け） |
| `modern.ts` | 現代の実業家・クリエイター |

## 1件の形

```ts
{
  id: "einstein-2",          // 一意。"<人物>-<連番>" で揃える
  origin: "en",              // もともと何語で語られたか
  en: "Try not to become a man of success, ...",   // ASCIIのみ
  ja: "成功者になろうとするな。むしろ価値のある人間になろうとせよ。",
  kana: "せいこうしゃになろうとするな。むしろかちのあるにんげんになろうとせよ。",
  author: "アルベルト・アインシュタイン",
  authorEn: "Albert Einstein",
  role: "物理学者",
  source: "1955年『LIFE』誌に載った知人の回想",
  note: "成功は他人からの評価だが、価値は自分が世界に何を与えたかで決まる、という対比。…",
}
```

## 守ること

### kana はひらがな・`ー`・`、`・`。` だけ
漢字やカタカナが1文字でも残ると、その問題はローマ字に展開できず**打ち切れなくなる**。
`ヒカル` → `ひかる`、`YouTube` → 読みをひらがなで書く。

### 帰属を裏取りしてから入れる
有名な名言ほど別人の言葉が本人のものとして流通している。実際にこの4件は調査の結果
差し替えた（一覧は CLAUDE.md の表にある）。

- 「最も強い種が生き残るのではなく…」＝ダーウィン → 経営学者メギンソンの要約(1963)
- 「我々は繰り返す行いそのものである」＝アリストテレス → ウィル・デュラントの要約(1926)
- 「成功は終わりではなく…」＝チャーチル → チャーチル協会が否定
- 「聞いたことは忘れる…」＝フランクリン → 中国由来の格言

裏取りが必要なときは `quote-verifier` エージェントに投げる。

### 出典をでっち上げない
`source` は書名・演説名・動画名が特定できるものだけ断定して書く。特定できないものは
**「〜の言葉として広く伝わる」のように断定を避ける**。それらしい書名を創作するのは最悪の失敗。
出典が確認できず、かつ別人の言葉だと分かっているものは**入れない**。

`modern.ts` は書物ではなく動画が出典になる。対談動画から採るときは**発言者が誰か**を必ず確認する
（ゲストの発言が混ざっていることがある。ヒカル氏の分を選んだときも、GACKT氏・立川志らく氏・
河村真木子氏の発言が同じ資料に含まれていた）。

### 日本語フィールドに他言語を混入させない
このセッション中に実際に3回起きた事故。`データ`→`데이터`(ハングル)、`分野別`→`分野별`、
`創る`→`создать`(キリル文字)。目視では気づきにくいので、
検証スクリプトに `FOREIGN = /[Ѐ-ӿ가-힯]/` のチェックを入れてある。**必ず検証を通すこと。**

### 難易度のバランス
かな22字以下の「短い問題」を一定数保つ（現在23件）。長いものばかり増やすと初心者が離脱する。

## 追加したら必ず検証する

```bash
npm run validate
```

kanaに打てない文字がないか、お手本どおり打って完了するか、英文がASCIIか、
`source`/`note`/`author`/`role` が空でないか、idが重複していないか、他言語が混入していないかを
一括で見る（`scripts/validate-quotes.ts`）。

最後に `✓ 全件OK` が出れば通過。件数の内訳も出るので、意図した分野に入ったかもここで確認する。

> このスクリプトは Node から直接 `.ts` を読むため、**import に `.ts` 拡張子まで書いてある**。
> Next.js や tsc は拡張子を補完するが Node の ESM は補完しない。アプリ側のコードと書き方が
> 違うのはそのため。真似してアプリ側に `.ts` を書かないこと（逆に `next build` が落ちる）。
